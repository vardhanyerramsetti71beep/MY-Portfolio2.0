## Problem Statement

Vardhan asked for "the cinematic portfolio," built from `public/Vardhan_Yerramsetti_Resume.pdf`. It already exists: Freefall 2.0 (commit `da7586d`) is a React 19 + Vite site with a canvas engine (`src/engine/freefallEngine.js`, 1,361 lines), procedural Web Audio, 7 chapters, and all of the resume's live projects.

The site doesn't need to be built. It needs to do its one job: get a recruiter for a Python full stack / cloud role to open a project, download the resume, or send an email within about 60 seconds. Today it puts three things between the recruiter and that goal:

- **A click gate.** `SystemLoader.jsx` blocks the site until the visitor picks "Enter with Audio" or "Enter Muted."
- **Sci-fi labels.** Names like "Quantum Gateway," "Terminal Uplink," and `AWS_CERT: ONLINE` hide what each section actually contains.
- **Claims the resume doesn't back up.** An interviewer can ask about any of them.

## What Makes This Cool

The movie-like descent stays: the warp field, 3D text flying past, and the sound. That's the part people remember. The polish makes the effect *frame* the work instead of hiding it. A recruiter who scrolls nothing still sees the name, role, top projects and contact links. A recruiter who scrolls gets the movie.

## Constraints

- Keep the existing stack: React 19, Vite 6, Tailwind 3, Lenis. Add no new dependencies.
- Keep the engine. Change content and layout, not the canvas internals.
- Deploys to Vercel, like the rest of Vardhan's projects.
- Fresher profile: B.Tech CSE, JNTU Kakinada (2018 to 2026), AWS Certified Cloud Practitioner. The tone should be confident, never inflated.

## Premises (agreed)

1. The audience is hiring managers and recruiters for Python full stack / cloud roles. The goal is an interview.
2. A recruiter gives the site 30 to 60 seconds, so name, role, top 3 projects, resume and email must all be visible before any scrolling or clicking.
3. Keep the cinematic feel, but rewrite the sci-fi labels in plain words a recruiter understands.
4. Every claim must be traceable to the resume.

## Approaches Considered

- **A) Recruiter-first polish (chosen).** Keep Freefall 2.0. Fix the first screen, the copy, the claims, and the fallbacks.
- **B) Case-study film.** Re-cut the site into 3 project stories. Rejected for now: more rewrite than the problem needs. Revisit after the 30-second test (see Assignment).
- **C) Fresh minimal rebuild.** Rejected: it throws away about 6,800 working lines to fix what is mostly a copy and layout problem.

## Recommended Approach: A

### 1. First screen with no gate
- The site renders right away, muted by default. Replace the `SystemLoader` gate with a small sound toggle in the corner; keep the `M` key shortcut.
- The first screen, over the warp field, shows:
  - `Vardhan Yerramsetti`
  - `Python Full Stack Developer · AWS Certified Cloud Practitioner`
  - the three flagship projects as links: Task Cloud Portal, OmniPulse CLV Engine, Music Recommender
  - `Resume (PDF)`, `Email`, `GitHub`, `LinkedIn`
- The navbar gets plain labels: Projects, Experience, Skills, Resume, Contact.

### 2. Plain-language copy
| Current | New |
|---|---|
| Selected Flagship Architectures | Featured Projects |
| Quantum Gateway / Portal | Contact intro (or cut) |
| Terminal Uplink | Contact |
| 8 Verified Production Deployments Reel | All Projects |
| Recruiter Decision Grid | Why Hire Me |
| `AWS_CERT: ONLINE`, `KERNEL: 2026.4`, `RUNTIME: STABLE` | Remove, or keep as decoration with `aria-hidden` |

### 3. Claim audit: resume as the source of truth
Fix each item in `src/data/portfolioData.js` and the components that repeat it:
- **`<85ms` stream latency** (Music Recommender, in `portfolioData.js:46,80,83`, `ArchitecturesSection.jsx:32,35,38`, `CapabilitiesSection.jsx:25,148` and `FreefallStage.jsx:39`). Not on the resume, which says ">90% classification accuracy" and "low-latency." Remove it, or replace it with a number Vardhan has measured.
- **`99.99% AWS Storage SLA`** (`ArchitecturesSection.jsx:19`). That's Amazon's S3 figure, not a project result. Remove.
- **"BG/NBD ... streaming under 85ms"** (`CapabilitiesSection.jsx:25,148`). The resume says the CLV engine has a "sub-15ms prediction latency." Use that.
- **"Demonstrated mastery" / "comprehensive mastery"** (`portfolioData.js:17,376`). Use the resume's own wording.
- **"8 shipped platforms."** The resume's summary says 8 production deployments but lists 6 projects. The site lists 8 (adding they-call-him-og and flask-google-form). Keep 8 only if both of those are live; otherwise say 6.
- **Keep, since the resume backs them:** -25% query latency (18.4ms to 13.8ms), >90% accuracy, sub-15ms CLV inference, <35ms tracker latency, sub-second first paint on MS Pickles.

### 4. Fallbacks
- Reduced motion: `freefall.css:2045` already has a `prefers-reduced-motion` block. Extend it so the engine skips the warp field and the 3D text, and the site becomes a normal scrolling page.
- Mobile: check the `max-width: 860px` path. The first screen must fit a 375px-wide screen with no horizontal scroll.
- Make sure the PDF link works without JavaScript.

### 5. Metadata
- `index.html`: add a title of the form `Vardhan Yerramsetti, Python Full Stack Developer`, plus a meta description and an Open Graph image, so the link previews well when shared on LinkedIn or WhatsApp.

## Open Questions
- Are `they-call-him-og-lemon.vercel.app` and `flask-google-form.vercel.app` live, and are they worth showing? That decides "6" vs "8."
- Is there a measured latency number for the Music Recommender? If not, the claim goes.
- Cut the Quantum Gateway chapter entirely, or shrink it to a short transition? Default: shrink it.

## Success Criteria
- A first-time visitor can name Vardhan's role and one project within 30 seconds, without scrolling (checked with the Assignment test).
- Resume, email, GitHub and LinkedIn are each one click from the first screen.
- Every number on the site matches a line in the resume (grep audit passes).
- With reduced motion turned on, there's no canvas animation and all content is still readable.
- Lighthouse on mobile: Accessibility ≥ 90; first contentful paint < 2.5s.

## The Assignment
Before writing any code, send the current site to 3 people (ideally one who hires engineers) and ask: "Open this, and after 30 seconds close it. What's my role, and what's one project you remember?" Write their answers in `docs/designs/recruiter-test.md`. If 2 of 3 can't name a project, the first-screen work (step 2) moves ahead of everything else. Run the same test again after the polish.

## What I noticed about how you think
- You didn't ask for a portfolio from scratch. You asked to "use this," your resume, and that resume already shows real numbers (18.4ms to 13.8ms). That instinct for measured results is your strongest asset, and the site should lead with it.
- You picked the recruiter-first premises and the polish approach without hesitating. You'd rather ship a better version of what exists than start over, which is the right call.
- You already built a 6,800-line cinematic site. That's agency. The next skill is editing: cutting what doesn't help the person you want to reach.
